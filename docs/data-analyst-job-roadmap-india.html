01

Phase 0

Think like an analyst before using a tool

The difference between a report-maker and an analyst is the quality of the question. Start every project by writing an analytical brief.

The seven-line analytical brief

  1. Decision: What decision should this analysis help someone make?
  2. Stakeholder: Who will use the answer?
  3. Question: State one precise business question.
  4. Metric: Define the primary calculation.
  5. Grain: What does one row represent?
  6. Time: Which dates are included and why?
  7. Limitations: What cannot be concluded from this data?

Example: A sales manager needs to decide which product categories to promote. Analyse completed orders over four quarters, define revenue as SUM(quantity * unit_price * (1 - discount)), compare category growth, and check whether a small customer group drives the result.

Business metrics you must define correctly

Know the formula, denominator, and appropriate business use for each metric.

02

Phase 1

Excel and data quality

Excel remains central to reporting, ad hoc analysis, and stakeholder work. Treat it as a serious analytical environment, not a beginner tool.

Data hygiene

  • Find blanks, duplicates, invalid dates, inconsistent category labels, and implausible numeric values.
  • Preserve the raw file and transform in a cleaned-data sheet or new columns.
  • Use tables, filters, named ranges, data types, sorting, and freeze panes deliberately.
  • Clean text with TRIM, CLEAN, LOWER, UPPER, and SUBSTITUTE.

Formulas analysts use

  • Logic: IF, IFS, AND, OR, IFERROR.
  • Aggregation: SUMIFS, COUNTIFS, AVERAGEIFS.
  • Lookups: XLOOKUP, INDEX + MATCH.
  • Dates: DATE, YEAR, MONTH, EOMONTH, NETWORKDAYS.
  • Dynamic arrays: FILTER, SORT, UNIQUE.

Analysis and reporting

  • Create PivotTables and PivotCharts; group dates by month, quarter, and year.
  • Use slicers and timelines only when they create a useful analysis path.
  • Use lines for trends, bars for comparisons, scatter plots for relationships, and tables for exact values.
  • Avoid 3D charts, decorative colours, crowded pie charts, and dashboards without a decision.

Excel portfolio deliverable

Retail sales performance dashboard

Create Raw_Data, Cleaned_Data, Analysis, Dashboard, and Data_Dictionary sheets. Show monthly trend, category performance, region performance, top products, KPI cards, filters, and a written insight box.

Competency gate

Turn a messy file into a decision

Given a raw sales file, clean it, calculate revenue, create a PivotTable report, identify the strongest and weakest segments, and explain three actions the business should consider.

03

Phase 2 / Highest-value skill

SQL: learn to reason in tables

SQL is the most consistently tested technical skill for analyst roles. Learn it as a method for reasoning about grain, relationships, and evidence, not a list of commands.

Relational thinking

Fact table

Records measurable events: an order, session, payment, or delivery.

Dimension table

Describes events: customer, product, date, category, or region.

Grain

The real-world meaning of one row. State it before every join or aggregation.

Foundation to fluency

  1. Master SELECT, aliases, DISTINCT, WHERE, ORDER BY, LIMIT, and null handling.
  2. Use IN, BETWEEN, LIKE, CASE WHEN, aggregates, GROUP BY, HAVING, and date functions.
  3. Learn INNER, LEFT, RIGHT, FULL OUTER, cross, and self joins. Prefer LEFT JOIN when the base population must remain intact.
  4. Build readable CTEs with WITH; know UNION ALL versus UNION.
  5. Use ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD, and windowed sums or averages.

Validate every join

The most common analyst error is an accidental many-to-many join that duplicates values. Check the expected row count and whether the primary key remains unique before believing the result.

-- Does the order identifier remain unique after this join?
SELECT
  COUNT(*) AS rows_after_join,
  COUNT(DISTINCT order_id) AS distinct_orders
FROM joined_data;

SQL problem set

  1. Revenue, order count, and AOV by month.
  2. Top five products by revenue within every category.
  3. Repeat customers and interval between purchases.
  4. Monthly revenue with prior-month revenue and percentage growth.
  1. First-purchase cohorts and monthly retention.
  2. Late orders by state and seller.
  3. Products with rising revenue but falling margin.
  4. RFM segments based on recency, frequency, and monetary value.

SQL quality checklist

  • Does every selected non-aggregated field appear in GROUP BY?
  • Did a join multiply rows?
  • Does COUNT(*) mean rows, or should it be COUNT(DISTINCT order_id)?
  • Are nulls and date boundaries intentional?
  • Do totals reconcile with a simple control query?
  • Can another analyst read the query structure in one pass?

Competency gate

Prove SQL fluency

Solve a multi-table business problem with joins, CTEs, date logic, and a window function. Validate output and explain the query in plain English.

04

Phase 3

Power BI first. Tableau with purpose.

Power BI is the primary BI tool for this roadmap because it appears frequently in Indian analyst, reporting, MIS, and BI roles. Learn Tableau to demonstrate flexibility and publish a public dashboard.

Power Query: prepare data deliberately

  • Connect to CSV, Excel, folders, SQL, and web sources.
  • Profile column quality, distribution, and errors; set data types deliberately.
  • Filter, replace, split, merge, fill, deduplicate, pivot, unpivot, append, and merge queries.
  • Name each transformation step and avoid undocumented manual changes in the report view.

Model first, visualise second

Build a star schema: dimensions such as Date, Customer, Product, and Region should filter a central FactSales table through one-to-many relationships.

  • Create and mark a dedicated date table.
  • Prefer single-direction filtering unless a documented reason requires otherwise.
  • Hide technical keys from report consumers.
  • Avoid one giant flat table when the source can be modelled.

DAX measures, not magic numbers

A calculated column is stored row by row. A measure is evaluated in the current filter context. Use measures for KPIs and validate each one against a small manual calculation.

Total Revenue = SUMX(FactSales, FactSales[Quantity] * FactSales[Unit Price])

Total Orders = DISTINCTCOUNT(FactSales[Order ID])

Average Order Value = DIVIDE([Total Revenue], [Total Orders])

Revenue Previous Month =
CALCULATE([Total Revenue], DATEADD(DimDate[Date], -1, MONTH))

Revenue MoM % =
DIVIDE([Total Revenue] - [Revenue Previous Month], [Revenue Previous Month])

Learn CALCULATE, filter context, row context, FILTER, ALL, REMOVEFILTERS, RELATED, DIVIDE, and basic time intelligence.

Dashboard design rules

  • Place purpose, date coverage, and KPI definitions in view.
  • Use hierarchy: headline KPIs, trend, drivers, then detail.
  • Use one visual per question.
  • Label currencies, units, percentages, and comparisons.
  • Use accessible contrast and do not depend on colour alone.
  • Reserve red and green for negative and positive signals consistently.
  • Add drill-through, tooltips, and detail only when they enable a decision.
  • End with key findings and actions, not only charts.

Tableau essentials

Learn dimensions versus measures, marks, filters, calculated fields, table calculations, parameters, dashboards, and actions. Build one Tableau Public dashboard with a different question or dataset from your Power BI report.

Competency gate

Deliver a stakeholder-ready report

Receive raw multi-table data, transform it, build a star schema, create validated measures, publish an interactive report, and explain the top three business actions it supports.

Python makes cleaning and exploration repeatable beyond spreadsheets. For an analyst role, master tabular data workflows before algorithms.

Notebook discipline

  • Use a clear structure: title, business question, imports, loading, cleaning, analysis, visuals, findings, limitations, next steps.
  • Restart and run all cells before publishing. A notebook that only works in your session is not reproducible.
  • Inspect before modifying: shape, types, missing values, duplicates, distributions, and unique values.
import pandas as pd

sales = pd.read_csv("data/raw/sales.csv", parse_dates=["order_date"])
sales.info()
sales.isna().sum()

sales["revenue"] = sales["quantity"] * sales["unit_price"] * (1 - sales["discount"])

monthly_revenue = (
    sales.groupby(sales["order_date"].dt.to_period("M"), as_index=False)["revenue"]
    .sum()
    .rename(columns={"order_date": "month"})
)

pandas skills to practise

  • Load CSV, Excel, JSON, and SQL query results.
  • Inspect with head, shape, info, describe, nunique, and value_counts.
  • Select with loc, boolean filters, query, and isin.
  • Clean with astype, to_datetime, string methods, replace, fillna, and drop_duplicates.
  • Combine with merge and concat; validate merge keys.
  • Aggregate with groupby, agg, pivot_table, and transform.
  • Reshape with melt, pivot, and stack/unstack when useful.
  • Avoid slow row-by-row apply when vectorised operations express the same logic.

Visualisation

Use lines for trends, bars for categories, histograms and box plots for distributions, scatter plots for relationships, and heat maps for cohorts or compact comparison. Every chart needs a descriptive title, meaningful axes, readable labels, and a statement of what it shows.

Competency gate

Publish reproducible evidence

Turn raw public data into a clean analytical table, perform grouped analysis and joins, create three useful charts, and publish a notebook that runs from top to bottom without error.

06

Phase 5

Statistics and business analytics

Statistics lets you tell signal from noise. The aim is not to recite formulas. It is to make measured recommendations with honest uncertainty.

Descriptive statistics

  • Population versus sample.
  • Mean, median, mode, range, variance, standard deviation, percentiles.
  • Skewness, outliers, and when a median represents a typical customer better than an average.
  • Distribution shape and why one summary number is rarely enough.
  • Correlation, causation, and confounding variables.

Inference

  • Random sampling and sampling bias.
  • Confidence intervals as a plausible range under the sample method.
  • Null and alternative hypotheses.
  • Type I and Type II error.
  • p-values as evidence under model assumptions, not probability the null is true.
  • Statistical versus practical significance.

A/B testing, correctly

  1. Define the decision, primary metric, guardrails, audience, and duration before launching.
  2. State the null and alternative hypotheses.
  3. Check random assignment, sample-ratio mismatch, tracking quality, and novelty effects.
  4. Compare absolute and relative impact.
  5. Report a confidence interval and test result.
  6. Decide using statistical evidence and business impact.
  7. State limitations: seasonality, multiple testing, incomplete tracking, or sample size.

Good interpretation: Variant B increased checkout conversion by 0.7 percentage points. Its interval excludes zero, making the effect statistically credible under the assumptions. Before rollout, check that refund rate and AOV did not fall and estimate incremental monthly profit, not only conversion.

Patterns every analyst should recognise

Funnels

Locate the largest absolute and relative drop-off.

Cohorts

Group users by first activity and observe retention over time.

Segments

Compare meaningful groups such as channel, geography, or tenure.

Pareto

Find whether a minority drives most outcomes.

Variance

Explain actual versus target, budget, or prior period.

Root cause

Investigate drivers without claiming causality from description alone.

Competency gate

Recommend with appropriate caution

Explain whether a metric change is meaningful, state assumptions behind the conclusion, and translate the result into a cautious business recommendation.

Five projects that prove you can do the job

Portfolio quality standard

  • A recruiter can see the business question in under two minutes.
  • Every dataset has source, grain, range, and limitations.
  • SQL, Python, and dashboard artefacts are organised and reproducible.
  • Findings use specific numbers and dashboard evidence.
  • Recommendations state owner, action, expected outcome, and success metric.
  • Raw data remains preserved and cleaning is documented.
  • Claims separate observation, interpretation, and recommendation.
  • Descriptive data never becomes an unsupported causal claim.

Phase 7

Hiring playbook for India

Your technical work only helps if it is easy for recruiters and interviewers to evaluate. Package projects clearly, practise explanation, and run an organised application system.

Interview preparation

SQL

  • WHERE versus HAVING.
  • Join types and duplicate-row diagnosis.
  • COUNT(*) versus COUNT(column) versus distinct count.
  • UNION versus UNION ALL.
  • CTEs, ranks, running totals, LAG, cohorts, top-N per group.

Excel and Power BI

  • Lookups, conditional aggregation, and PivotTables.
  • Power Query versus DAX.
  • Calculated columns versus measures.
  • Star schema, filter direction, context, CALCULATE.
  • Dashboard validation and improvement.

Python

  • Series versus DataFrame.
  • Merge types and duplicate-key risk.
  • groupby, agg, transform, pivot_table.
  • Missing values, vectorisation, notebook reproducibility.

Business case

  1. Clarify metric, scope, and comparison.
  2. Break the outcome into drivers.
  3. Segment by time, geography, channel, product, and customer.
  4. Check tracking and seasonality.
  5. Prioritise the highest-impact driver.
  6. Recommend an action and monitor.

Project walkthrough script

Context: what decision did this support? Data: what was the grain and what joined? Method: how did you clean and validate? Insight: what specific pattern mattered? Action: what should happen next? Limitation: what can the data not prove? Keep the first answer under two minutes.

Resume and LinkedIn

Keep a fresher resume to one page. Include name, city, professional contacts, LinkedIn, GitHub, and portfolio links; a targeted headline; concise summary; grouped skills; strongest projects; then education.

Headline: Aspiring Data Analyst | SQL | Power BI | Excel | Python | Tableau

Strong bullet formula: action + tool/method + insight + business purpose.

Example: Built a Power BI sales and profitability dashboard from 9,000+ retail transactions using Power Query, star-schema modelling, and DAX; identified loss-making discount bands and proposed category-level guardrails.

Never invent commercial impact. With public data, say “identified” or “recommended,” never “increased company revenue.” Add GitHub, Tableau Public, and dashboard links to LinkedIn Featured. Post short project case studies: question, one visual, insight, action, link.

Application operating system

Maintain a tracker with company, role, job link, date applied, requested skills, referral/contact, resume version, status, follow-up date, and notes. Apply through LinkedIn, Naukri, Indeed, Wellfound, Internshala, company career pages, alumni, and referrals. Tailor project ordering and resume keywords only to skills you can defend.

The job-readiness check

Intensify applications when you can complete this list without a tutorial. The goal is demonstrated capability, not perfect confidence.

  • Build a Power BI report with Power Query, star schema, validated DAX, and purposeful interactions.
  • Publish one polished Tableau Public dashboard.
  • Build a reproducible pandas notebook with cleaning, joins, aggregation, and charts.
