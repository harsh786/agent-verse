Glossary

The vocabulary, defined once.

The vocabulary, defined once

The terms this manual uses in its own specific senses. Where a term has a chapter, that is where it is developed in full.

TermDefinition
Agent loopThe checkpointed state machine (initialize → retrieve → plan → execute → verify → route) that runs one goal. The substrate, not an option. (Ch 1)
Agent patternA control-flow shape: the rule deciding what the model is asked next. ReAct, plan-execute, reflection, and the rest are answers to that one question. (Ch 1)
AssemblerThe rule table that maps a goal's classified properties to a pattern config, appending safety patterns it can never remove. (Ch 1)
BulkheadA per-tenant concurrency ceiling, so one tenant's fan-out cannot starve the shared pool. (Ch 20, 28)
ChunkThe atom of retrieval: a span of a document with a stable id, embedded, scored, cited, and deleted as a unit. (Ch 4, 17)
Circuit breakerA guard that stops calling a failing dependency after repeated failures, failing fast or serving stale until it recovers. (Ch 16, 28)
ClassificationA datum's tag — public/internal/confidential/restricted — assigned at creation, driving handling, retention, residency, and deletion. (Ch 30)
CollectionThe unit of authorisation, embedding model, and lifecycle for knowledge — not a folder. (Ch 4)
Consensus verificationUp to three independent verifiers (primary, cross-model, judge) for high-stakes goals; disagreement escalates to a human. (Ch 1)
Decision traceThe record of every runtime decision (pattern, model, tools, policy) with its reason — the agent-specific observability signal. (Ch 11)
Degraded modeRunning with less when a dependency is down — lexical search without the embedder — rather than failing, and never fail-open on a fail-closed control. (Ch 28)
Fail closedWhen a check errors or is uncertain, block rather than proceed. The principle that makes guardrails trustworthy. (Ch 12)
GoalThe process abstraction: a natural-language objective the platform plans, executes, verifies, and completes. (Ch 19)
GroundingChecking that every factual claim in an output is supported by the evidence — deterministically first, then by entailment. (Ch 18)
GuardrailA deterministic check that can block input, tool calls, or output independent of the model's cooperation. (Ch 12)
HITLHuman-in-the-loop: a durable pause where a goal checkpoints, releases its worker, and waits for a human decision. (Ch 1, 23)
Hybrid retrievalVector + lexical (BM25) + trigram search merged by rank fusion — the correct default for enterprise corpora with identifiers. (Ch 2, 6)
Idempotency keyA key derived from goal + step + arguments so a retried write is recognised as the same write, not a new one. (Ch 28)
Ingestion pipelineThe 13-stage path (receive → … → PII redact → … → embed → index → emit) every document takes, hash-gated at stage 3. (Ch 5)
MCPModel Context Protocol: the device-driver layer where tools live in their own processes behind a uniform, per-tenant protocol. (Ch 19, 20)
Memory tierOne of seven stores (execution, reflexion, long-term, episodic, procedural, knowledge-graph, prospective), each with its own lifetime and trust. (Ch 3)
Poisoned memoryAn attacker-authored lesson written to memory and recalled into future prompts; prevented by provenance, quarantine, and untrusted treatment. (Ch 3)
Prompt recipeThe reconstructable record of a prompt — variant ids, context item ids, budget, model — stored instead of the full prompt. (Ch 8)
ProvenanceThe origin chain of a datum — source, revision, extraction — used for both grounding and deletion. (Ch 30)
ReflexionReflection that outlives the run: a durable, scoped lesson extracted from failure and recalled for similar future goals. (Ch 1, 3)
RLSRow-level security: Postgres filtering every row by app.tenant_id, the independent database backstop to app-level tenant isolation. (Ch 13, 14)
RollbackApplying registered inverses in LIFO order to undo a failed goal's side effects, so failure leaves no half-built state. (Ch 1, 20)
ScopeOne of nine nested boundaries (tenant → API key → agent → collection → connector → tool → memory → policy → runtime) AND-ed to prevent leakage. (Ch 14)
Semantic cacheServing a repeated question's answer by embedding match rather than exact string — the largest cost lever on repetitive workloads. (Ch 2, 29)
Stall detectionHashing results to detect no progress across iterations, deterministic and resumable, so a loop cannot spin silently. (Ch 1)
Strategy readinessThe gateway checking whether a RAG strategy can actually run given the tenant's capabilities, delegating to a ready one rather than failing. (Ch 2)
TenantContextThe immutable, per-request identity that flows through everything and sets the RLS boundary — a top hub of the whole system. (Ch 13)
Tool risk classread / write_low / write_high / destructive — the classification that drives approval, rollback, and audit for a tool call. (Ch 1, 13)
Two-phase wiringThe app built once with in-memory services, then swapped to DB/Redis-backed ones in the lifespan — the source of most "works in tests, not in prod" bugs. (Ch 19)
VerifierThe only node with authority to end a run; judges the step against evidence, never against the actor's own reasoning. (Ch 1, 8, 18)
