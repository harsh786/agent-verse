Orientation

Voice turns an agent into something you can talk to, and it changes one thing above all: the latency budget. A user tolerates seconds of silence from a chat box and none from a voice that has started to reply. Every design decision in a voice agent — streaming, barge-in, model choice — is downstream of the fact that a person is listening in real time.

The pipeline is speech-to-text → intent → agent → text-to-speech, and the art is making it feel continuous: streaming transcription so the agent starts thinking before you finish, streaming synthesis so it starts speaking before it finishes thinking, and barge-in so you can interrupt.

The voice pipeline

The streaming voice session

A session that streams audio in, transcribes, routes, runs the agent, and streams speech back — orchestrated so the pieces overlap rather than run strictly in sequence.

Mechanism

The session runs a pipeline: incoming audio is converted and streamed to STT, the transcript routes to an intent handler that invokes the agent, and the response streams to TTS and back as audio. The overlap is the point — transcription runs while the user is still speaking, and synthesis starts on the first words of the response — so perceived latency is far below the sum of the stages.

Worked example

user: "what's the status of my invoice reconciliation?"
 STT streams the transcript as they speak → routes at end of utterance
 agent runs → first sentence ready → TTS streams it → user hears it
 while the agent is still forming the rest
perceived latency ≈ time to the first spoken word, not the full turn

At production scale

The streaming overlap is the whole game — a non-streamed voice pipeline (transcribe fully, think fully, synthesise fully) feels broken because the silences are unbearable. Measure time-to-first-audio, not total turn time. Voice sessions are also long-lived connections, which is a different scaling profile from request/response goals (chapter 32).

Failure modes

  • No streaming. Unbearable silences.
  • Measuring total turn time. Missing what the user actually feels.

Choose it when

  • Any real-time voice interaction.

Speech-to-text

Transcription with provider choice by language and latency — a fast local model for real-time, a cloud model for accuracy, selected like any other model role.

Mechanism

An STT engine abstracts multiple providers (Whisper API, faster-whisper for local low-latency, AssemblyAI), selected by language and latency needs (chapter 16). Streaming STT emits partial transcripts as audio arrives. Domain vocabulary hints improve accuracy on jargon where the provider supports them.

Worked example

real-time call, German audio

 streaming partials: "wie ist der..." → "wie ist der Status..."
 domain hint: ["GSTR-1", "Razorpay"] improves jargon accuracy

At production scale

STT is the accuracy foundation — a mis-transcription propagates to a wrong action. Route by language (an English model on German audio is poor) and by latency (local for real-time, cloud for batch accuracy). Full provider-routing treatment in chapter 16; the ingestion side (transcribing recordings) is chapter 5.

Failure modes

  • Language-blind routing. Poor transcription on non-default languages.
  • No streaming. Latency the user feels.
  • Jargon errors. Domain terms mangled without hints.

Choose it when

  • Any voice input.

Intent routing and barge-in

Turn an utterance into an action — a command, a question, or a goal — and let the user interrupt the agent mid-sentence, which is what makes voice feel conversational.

Mechanism

An intent router classifies the transcript: a direct command (execute), a question (answer), or a goal (submit to the agent loop). Barge-in detects the user speaking while the agent is talking and cancels the TTS immediately — cooperative cancellation of the output stream — so the user can interrupt naturally rather than waiting for the agent to finish.

In AgentVerse

  • app/voice/intent_router.pyroute_voice_command()
  • app/voice/streaming.pybarge-in via stream cancellation

Worked example

agent (speaking): "The reconciliation found three discrepancies. The first—"
user (interrupts): "just tell me the total"
 barge-in detected → TTS cancelled immediately
 intent router: question → answer directly → "The total variance is ₹4,120."
without barge-in, the user would have to wait through the whole explanation

At production scale

Barge-in is the feature that separates a voice agent from a voice menu. It requires the output stream to be cancellable at any point (chapter 1's cooperative cancellation applied to audio) — a TTS that cannot be interrupted makes every interaction feel like waiting on hold. Intent routing keeps cheap requests (a question) off the full agent loop.

Failure modes

  • No barge-in. The user waits through everything.
  • Everything routed to the full loop. A simple question taking a full goal.

Choose it when

  • Any conversational voice agent.

Text-to-speech

Streaming synthesis with provider choice by quality, latency, and voice — from a fast local voice for real-time to a premium cloud voice where quality matters, with a browser fallback.

Mechanism

A TTS engine abstracts providers (ElevenLabs, OpenAI, Azure, Kokoro, macOS say, a browser fallback, and others), streaming synthesis so audio starts on the first sentence. Selection trades quality against latency and cost (chapter 16): a premium voice for a customer-facing line, a fast local voice for internal tools, a browser fallback when nothing else is available.

customer-facing line → ElevenLabs (premium voice), streamed
internal tool       → Kokoro (fast local), streamed
provider down       → browser_fallback (Web Speech API)
first sentence synthesised and playing while the rest is generated

At production scale

Streaming TTS is what lets the agent start speaking before it finishes thinking — the second half of the low-latency story. The provider spread (premium to local to browser fallback) is the same reliability pattern as the model router: quality where it matters, cheap where it does not, and a fallback that always works. Full routing treatment in chapter 16.

Failure modes

  • Non-streaming synthesis. A pause before the agent speaks.
  • No fallback. Silence when the provider is down.

Choose it when

  • Any voice output.

What is missing here

  • Native speech-to-speech models. The pipeline is STT→LLM→TTS; end-to-end speech models would cut latency further but are harder to govern and cite.
  • Emotion and prosody control. Synthesis is largely neutral; conveying appropriate tone is future work.
  • Voice-specific guardrails. The text guardrails apply to the transcript, but audio-specific concerns (voice cloning, spoofing) are not addressed.
  • Full HITL over voice. Approving a gated action mid-call is thinner than the text/console approval flow (chapter 23).
